# Project Northstar: FINAL 92 — The Lock-In (V60)

This is the public-safe PWA repository for the October 1–December 31, 2026 FINAL 92 campaign. It is a direct upgrade of the V59 Ironwall codebase, preserving the Blacksite visual system, 52-brick fortress, XP/levels, Reset, Health, Photos, Mountains, Goals, Reviews, Data, backup/restore, and offline PWA architecture.

## FINAL 92 structure

- Master campaign: **FINAL 92 — THE LOCK-IN** (Oct 1–Dec 31, 2026)
- Discipline engine: **Ironwall 52** starting at **0/52**
- Historical best wall run: restored as legacy evidence, not active progress
- Permanent No-Slither 90/90 achievement stays legacy proof and contributes no new-campaign XP
- October **STRENGTHEN**, November **INTENSIFY**, December **PROVE IT**
- Eight brick-gated rewards at 7/14/21/28/35/42/49/52
- Three monthly phase gates
- Six Iron Ledger benchmark missions; Hevy remains workout-detail source of truth
- Recovery Command and nine-stage Return-to-Mountains progression

## Daily rule

A brick requires explicit closeout, integrity kept, and all six standards:

1. Prayer / study
2. Hydration + creatine (3 L water + established creatine routine)
3. Rehab / PT
4. Hevy / training-plan obligation
5. LooksMax / presentation
6. Attention controlled

Support metrics such as protein, sleep, outside/daylight, bodyweight, glucose readiness, recovery quality, swelling, and Body Status are logged separately and feed Weekly/Monthly Reviews. They are not hidden brick gates.

## Restore contract

**Current V60 code owns the current structure. Older backups own historical evidence.**

V59 and older supported restores migrate non-destructively. Old active campaigns, goals, rewards, tasks, reviews, recovery data, Mountains evidence, photos, and other records are preserved in history/archives. Old active state cannot replace the FINAL 92 dates, 0/52 wall, reward ladder, current six standards, or current navigation.

For the supplied user migration, use the separate private V60 restore in Data → Restore. Never upload that private restore to a public repository.

## Public/private boundary

The clean repository contains no private backup, photos, health record, financial balances, journal entries, or private task seed. Full private data belongs only in the separate checksum-verified restore file.
